# CLAUDE.md

Personal portfolio for Troy Bay (front-end developer & UI/UX designer). Single-page React site deployed to GitHub Pages at https://ztreuse.github.io/Portfolio/.

## Stack

- React 19 + Vite 7, plain JavaScript (JSX), no TypeScript
- Tailwind CSS v4 via `@tailwindcss/vite`; there is no `tailwind.config.js`, and theme tokens live in `src/index.css` under `@theme`
- `motion` (formerly Framer Motion) for animation, imported from `motion/react`
- `lenis` for smooth, weighted page scrolling (`hooks/useSmoothScroll.js`; off for reduced motion)
- `react-icons` for all icons (`si` brand logos, `lu` Lucide UI icons, `fa6` profile icons)
- `three` for the preloader's 3D coffee cup (lazy-loaded chunk, `src/three/coffeeScene.js`)
- `react-type-animation` for the hero name, `@emailjs/browser` for the contact form
- No router. In-page links use `{...sectionLink('id')}` from `hooks/useCleanAnchorLinks.js`. Every section is a normal `#id` anchor (the hash showing for those is fine), except Home (`hero`): it points at the plain site URL and the hook scrolls it to the top and clears the hash, because the owner wants Home to show `/Portfolio/`, not `/Portfolio/#hero`. `scroll-padding-top` in `index.css` clears the fixed navbar.

## Commands

```bash
npm run dev      # http://localhost:5173/Portfolio/  (the /Portfolio/ path is required)
npm run lint
npm run build
npm run deploy   # builds and publishes dist/ to GitHub Pages; only when asked
```

After any change, run `npm run lint` and `npm run build`. Both must pass before saying the work is done.

## Conventions

- **Content goes in `src/data/`, not in JSX.** Name, contact info, socials, nav links and EmailJS IDs are in `data/site.js`. Hero, Footer, Navbar and Contact read from it; never hardcode those values in a component.
- **Socials are professional profiles only:** LinkedIn, GitHub and JobStreet (`socials` in `data/site.js`, each with a `handle`). The owner removed Facebook and Instagram as unprofessional; don't add personal social media. The same list feeds the hero and phone-menu icons and the footer's "Find me on" rows. Contact no longer lists them: the owner removed them there as redundant with the footer right below. JobStreet has no brand icon, so it uses `FaBriefcase`.
- **Every page section uses `<Section id eyebrow title description>`.** It provides the spacing (`py-20 sm:py-28`), the `max-w-6xl` container and the heading style. New sections follow the same pattern. Headings are left-aligned, on every section. `align="center"` still exists in `SectionHeading` but is unused: Skills was centred until the owner found its centred title beside the right-hand "05" unbalanced and chose to align it left like the rest.
- **Section numbering:** eyebrows are written `01 — About`, `02 — Projects`, `03 — Experience`, `04 — Certifications`, `05 — Skills`, `06 — Contact` (Projects moved up to second at the owner's request, since recruiters look for it first) (navbar links are unnumbered), but `SectionHeading` shows only the label ("About"); the number only drives the faint ghost number behind the title (the owner removed it from the small label as redundant). A new section needs a `navLinks` entry in `data/site.js` and renumbered eyebrows. The eyebrow names the section; the title must not repeat it (the owner found "01 — About / About me" redundant). Titles are short statements: About "Get to know me" (the owner wanted a plain synonym for "About", not a slogan; "Designer who codes" was rejected as silly), Experience "Where I've worked" (work only since Education moved to About), Certifications "Credentials I've earned", Skills "Tools I build with", Projects "Selected work", Contact "Let's work together". Check that long words fit at 360px.
- **Navbar:** a conventional full-width top bar (`components/layout/Navbar.jsx`), with the logo on the left and links on the right, fixed and always visible.
  - **Logo:** the angular T mark (`assets/images/logo-mark.svg`) sits beside the TROY wordmark.

    - **Tab icon:** `public/favicon.svg` is the same mark on a dark rounded square.
    - **Rejected icon designs:** "TB" in Arial, plus hooked, ripple, ring, layered, I-beam cursor and stamp T designs.
  - **Shape:** it never changes size or shape. It's transparent at the top and fine see-through glass once scrolled (`bg-ink/60`, `backdrop-blur-xl backdrop-saturate-150`, no drop shadow), finished with a bottom hairline that fades out toward both ends (the owner asked for it to feel more premium; it used to be a heavy `bg-ink/90` band with a shadow).

Hit-testing with `elementsFromPoint` didn't work: most background layers here are click-through, so it saw through them. Anything new that's light behind the bar needs `data-nav-light`.
  - **Links** (redesigned when the owner asked for a different font, styling and unique animation): Big Shoulders Display, bold, uppercase, `tracking-[0.14em]`, 15px, like the section labels. On hover the letters breathe apart to `0.2em` and brighten (no movement; rolling/flipping/sliding hovers were rejected before). The active link is full white (dark on light glass) with an elastic dash under it (`ElasticDash`): an 18px glowing `accent-strong` line whose two ends move on separate springs, a quick one (`LEAD`) for the end heading toward the new link and a slow one (`TRAIL`) for the other, so it stretches across like liquid (measured: 18 → 50 → 18px) and settles back into a dash. It replaced a springing diamond (the owner asked for something else) and before that a sliding underline. Each link holds its width with an invisible copy at the widest letter-spacing, so the hover breathing never shifts the other links (or the dash). On load the links sharpen in one by one from a 6px blur. The phone menu uses the same uppercase display type (`text-lg`).

    - **Panel:** a dark glass card with a taupe glow, the active link marked by a glowing bar and highlighted row, and the social icons along the bottom.
    - **Closing:** a dim backdrop closes it on tap, and Escape closes it too.

- **Preloader:** `components/layout/Preloader.jsx`.
  - **3D cup (default): Three.js** (`src/three/coffeeScene.js`), loaded with `import()` as its own ~130 KB gzip chunk.
    - **Loading:** the import starts at module load (`scene3DModule`, as soon as the app starts), not when the preloader mounts. While it loads (`mode: 'pending'`) only the glow and counter show.
    - **Fallback:** the flat SVG cup appears only if 3D can't be used (reduced motion, no WebGL2), the load fails, or it isn't ready within `SCENE_WAIT` (2.5 s). It then stays for good, so the cup never swaps mid-load. The owner saw the flat cup flash first when it was shown while loading.
    - **Dev server:** `vite.config.js` pre-bundles `three` and the post-processing modules it imports (`optimizeDeps.include`; add any new `three/examples/jsm` import there too). Otherwise the dev server finds the dynamic import late, optimizes it on the fly and reloads the page mid-load.
    - **History:** the owner asked for "something like Three.js" with a coffee overflow that transitions into the portfolio. An earlier hand-rolled raymarched 3D cup was removed at their request.
    - **Scene:** a realistic studio product render. The owner asked for realism after finding the glass version "unfinished, not appropriate". The realism comes from the setup around the PBR materials (MeshPhysical/MeshStandard), not from the material type:
      - **Studio reflections:** `studioEnvironment()` bakes a dark room with softbox panels (a big warm key upper-left, a tall rim strip, an overhead light, a faint fill card) into a PMREM environment map (`environmentIntensity` 0.9).
      - **Surface detail:** procedural noise textures as roughness and bump maps on the glaze, saucer and table; the crema has a fine bump.
      - **Tabletop:** a dark, slightly rough disc that catches the soft shadow, with a radial `alphaMap` fade so it melts into the page. The canvas is opaque with an `ink` background.
      - **Antialiasing:** the composer renders into a multisampled target (`samples: 4`), because rendering through it skips the canvas's own antialiasing; the cup's rim looked jagged and flickered. The glaze bump is subtle (`bumpScale` 0.04) so it doesn't sparkle along the rim, and the coffee column sits 0.004 inside the inner wall (no z-fighting).
      - **Post-processing:** `EffectComposer` → `RenderPass` → `BokehPass` (gentle depth of field; its focus tracks the camera-to-target distance every frame, including the dive) → `OutputPass`. Pixel ratio capped at 1.5.
      - **Rejected:** `GTAOPass` ambient occlusion, which drew the steam sprites as dark blocks.
      - **Wet coffee look** (`LIQUID_LOOK`, shared by every liquid material): roughness 0.1 with a glossy clear coat, plus a subtle amber `sheen` (0.5, `#9a6238`) standing in for light passing through thin coffee. The rivulet sheet gets the same thickness shading from a blurred copy of its alpha map (`rivuletShade`).
      - **Rejected:** strong warm backlights (a 2.6 rim plus a behind-left amber light) glared across the glossy saucer and table and turned them tan, and a full-strength amber sheen made the coffee look like caramel.
      - **Steam:** two crossed camera-facing planes (around the vertical axis) whose shader (`STEAM_FRAGMENT`) draws curling wisps from domain-warped fbm noise. It rises from the whole coffee surface: as wide as the cup's mouth at the base (the planes are 1.2 wide, their base on the coffee level, the front wall hiding it while the level is below the rim), made of many fine strands that sway, spread a little and break into patches as they rise, faded at the bottom and top. The owner pointed out that a single column from the centre was wrong for a whole cup mouth. The wisps are soft and billowing (low-frequency noise sampled in coordinates that rise over time, gentle thresholds that blur further with height, spreading to 1.0 wide at the top), so it keeps flowing instead of looking like static streaks (the owner's feedback). It replaced stacked round sprites, which the owner said looked like circles piled on each other. Their overall strength eases in over a couple of seconds once the cup is half full (a smoothed value, not tied to the count, which can jump; the owner saw it pop in) and fades out as the camera swoops.
      - **Rim:** a true half-round lip as wide as the wall, starting exactly where the outer wall ends and landing on the inner wall, so there's no step or ridge.
      - **Meniscus:** a thin, lighter lathe ring where the coffee meets the wall, so the crema curves up the wall instead of stopping in a hard line. It sits 0.0008 above the crema; a polygon offset made it show through the front wall.
      - **Cup:** a glazed ceramic cup (`GLAZE #d8cdc1` cream-taupe, a satin body under a glossy clear coat), lathe-turned with a foot ring and a rounded rim. The handle is an ear-shaped `TubeGeometry` (slightly flattened) whose ends sink into the opaque wall.
      - **Saucer:** a glossy dark ceramic lathe saucer.
      - **Coffee:** visible from the elevated three-quarter camera.
      - **Rejected:** a transmission glass mug, which looked frosted at this budget.
      - **Tone mapping:** AgX (filmic) at exposure 1.15.
    - **Colour:** a heavy, deep brown in the site's taupe family (the owner asked for heavy brown, not golden/caramel; an earlier latte taupe `#7a5c48` read golden under the studio light). One `LIQUID` colour (`#4a3529`) is shared by the stream, the drips and the pool (`LIQUID_LIGHT #5f4738` under the thickness-shaded films, whose vertex colours are neutral, not orange-shifted), so the overflow looks like the same coffee on the cup and on the saucer. The pool's base colour is darker (×0.3) with a softer clear coat, because it faces the overhead light while the drips face sideways. The amber sheen is a muted `#5c4234`.
    - **Crema:** foamy (`cremaTextures`, the owner asked for a foamier head). The colour map is a taupe-brown gradient (`#8c7665` centre to the `LIQUID` edge) with soft lighter microfoam patches, faint swirls and 9,000 bubbles of mixed sizes (6% larger ones with a faint light rim). A matching bump map raises each bubble as a small dome with a darker cell wall (`bumpScale` 1.6, roughness 0.85). The meniscus ring is `#7d6858`.
    - **Swell:** at the brim, a low dome that bulges inside the mouth and then creeps out to slightly wider than the rim (see Timeline), so the drips run out from under it (`swellGeometry`, crema projected flat from above; a sphere's own UVs pinched the texture's dark edge into a blob).
    - **Overflow drips:** seven beads of coffee (`dripGeometry`). Each starts on top of the rim, rolls over the half-round lip (`LIP_ROWS`, following the lip's curve and normal) and runs down the wall to its `endY` (some stop part-way). The cross-section is rounded (7 vertices across, thickest in the middle and thinning to nothing at the edges) and hugs the surface; width tapers and wobbles. They're revealed top-down with `setDrawRange`, led by a flattened drop wide enough to round off the film's front, gliding smoothly between the film's points. The drop gathers on the outer side of the lip and swells in (smoothstep) as the drip reaches the wall. Shown on top of the rim it stuck up like an ear at the cup's silhouette, and popping in at full size looked unrealistic (the owner noticed both). Each drip runs at its own pace and slowly, like viscous coffee (1.8–2.4 s from the rim, staggered 0.2 s; the owner found sub-second drips and a fast-spreading pool unreal). The films carry thickness shading in vertex colours: thin edges lighter, thick middles darker (`dripMat`, over `LIQUID_LIGHT`). Rejected: flat three-vertex films that started square-cut beside the rim and stood off the wall (the owner saw them as floating strips).
    - **Overflow sheet:** besides the seven main drips, coffee runs over the whole rim in many uneven rivulets: a lathe film around the outside of the cup and over the lip, whose `alphaMap` (`rivuletTexture`: a band at the lip, 38 streaks of varied width and length, each tapering and ending in a bead) slides down the cup (`offset.y`, smoothstep) so the rivulets flow out from the rim; `alphaTest` keeps their edges crisp. Added after the owner shared a video of real overflowing coffee.
    - **Pour into the overflow:** the stream keeps pouring for a moment after 100% (cut from 0.5 s), since that's what pushes the coffee over.
    - **Pool:** an uneven glossy puddle (a gently wobbled circle). It waits until the first full-length drip's drop reaches the saucer (`POOL_START`), then the saucer fills: the pool widens and its surface rises (`position.y`), so its edge meets the saucer's sloping floor. Its colour is `LIQUID` × 0.18 (it faces the overhead light, and a deeper puddle reads darker), matching the rivulets on screen. The owner saw the pool appear before any coffee ran down, which looked unrealistic.

## Design system

| Token (`src/index.css`) | Value     | Use                          |
| ----------------------- | --------- | ---------------------------- |
| `ink`                   | `#161513` | page background              |
| `ink-deep`              | `#0f0e0d` | spare darker shade (the footer now uses `ink`) |
| `surface`               | `#1f1d1a` | cards, inputs                |
| `line`                  | `#2d2925` | borders, dividers            |
| `accent`                | `#9f8f81` | brand accent (taupe)         |
| `accent-strong`         | `#c9bcaf` | accent text, hover states    |
| `dimension`             | `#403b37` | Experience's "dimension" circle |
| `screen`                | `#c2b19a` | Contact and footer background (the desk film's screen glow) |

- **Fonts:** two roles, set after the owner found Inter-only headings plain next to Groove Grounds and picked the condensed option from rendered previews (Archivo Expanded, Bricolage Grotesque and Unbounded were the alternatives).
  - **`font-heading`: Big Shoulders Display** (Google Fonts, weights 600–900), always uppercase and heavy (`font-black` for the hero name, section titles and wordmarks; `font-extrabold` for card and job titles), with `tracking-[0.005em]`–`[0.01em]` and tight leading (`0.85`–`0.95`). Used for the hero name, section titles, card and job titles (projects, certifications, skills groups, experience), the footer sign-off and wordmark, the chapter numbers and both loader percentages.
  - **Labels are Big Shoulders too:** every small uppercase label (section eyebrows, project roles, experience dates, form labels, "Find me on", "Read more", the cursor's View/Drag tag) plus the hero's "Hello there, I'm" label, cycling role line and Scroll cue. The owner felt the Inter versions didn't fit beside the condensed headings and asked for all of them to change.
  - **`font-display` and `font-sans`: Inter** for everything read or clicked: body text, buttons, nav links, placeholders and the email address.
  - **Scale:** section titles are `text-[clamp(3.25rem,10vw,8.5rem)]` so the page keeps the hero's volume; the hero name is `text-[clamp(5rem,22vw,13rem)]`. They used to be 48px Inter under a 136px hero name, which made everything after the hero feel quiet and templated.
  - **History:** Inter alone (tight, heavy, after dnyaneshgore.com) came before this; before that Onest, Zalando Sans Expanded and Poppins, and the owner once rejected Inter with Space Grotesk and JetBrains Mono as generic.
  - **Other fonts:** don't add monospace or cursive/script fonts.
- **Palette experiments:** a subtle matcha green secondary accent (`#9caf88` on the hero glow, eyebrow numbers, nav underline and icon hovers) was tried and reverted because the owner found it too minimal. Don't reintroduce it unasked; if the idea returns, it needs a bolder treatment.
- **Text colors:** headings `text-white`, body `text-stone-300`/`text-stone-400`.
  - **Muted text:** `text-stone-500` is only for large text (about 4:1 on `ink`). Small labels and fine print use `text-stone-400`, and form placeholders use `placeholder:text-stone-500`, to meet WCAG AA.
- **Keyboard focus:** one global `:focus-visible` outline (2px `accent`, 3px offset) in `index.css` base styles covers every link, button and field. Don't add per-component focus styles unless a control needs something different.
- **Press feedback:** `Button` scales to 0.97 and `IconButton` to 0.94 on `:active`. Titles use `text-balance` and section descriptions `text-pretty`.

## Gotchas

- **Base path is `/Portfolio/`** (`vite.config.js`). Files in `public/` must be linked through `import.meta.env.BASE_URL` (see `profile.resume`), not `/file.pdf`.
- **ESLint** doesn't see JSX usage for destructured or namespaced components, so the `no-unused-vars` rule ignores names starting with a capital letter and `motion`. Keep using `icon: Icon` destructuring and `motion.*`.
- **EmailJS:** the form fields are `user_name`, `user_email`, `subject`, `message`. Only the message used to arrive, because EmailJS fills only template variables whose names match and the template uses other names. So `templateParams()` in `Contact.jsx` sends each value under all the common names (`name`/`from_name`/`user_name`, `email`/`from_email`/`reply_to`/`user_email`, `title`/`subject`, `message`, plus `time`) via `emailjs.send`. Keep that mapping when changing the form.
- **Contact layout** (based on professional portfolio contact pages; the owner rejected an earlier boxed-cards version):
  - **Left, "Reach me directly":** the email large in the display font (`text-lg sm:text-xl`) with an underline that draws in on hover and an icon-only copy button, then the phone on a quiet line. The email only ever wraps right after the `@` (`<wbr>`), never mid-word.
  - **Right, a conversational form:** "What's your name?", "Your email", "What's it about?", "Your message" (the owner removed the 01–04 numbers). The inputs are underline-only and warm to taupe on focus. Placeholders are plain instructions ("Your full name", "Where can I reply?"); no sample names like "Jane Doe" or "jane@company.com", which the owner found AI-generic.
  - **Send:** the shared `Button` (pill with an arrow in a dark circle, spinner while sending), with the icon status line beside it. It stays a compact pill on every screen (on phones it sits at the left, `max-sm:self-start`); the owner rejected a full-width button on mobile.
- **Windows, case-insensitive filesystem:** keep folders lowercase (`components/`, not `Components/`). Imports are case-sensitive on the Linux build server.
- **Dev server:** after changing `vite.config.js` or installing packages, it needs a full restart (Ctrl+C, then `npm run dev`); a browser refresh isn't enough.
- **Images:** project screenshots are WebP (1600×900, quality 0.84, about 50–90 KB each; they were 1–2 MB PNGs). Use WebP for new images, give `<img>` its `width`/`height` so loading doesn't shift the layout, and use `loading="lazy"` below the fold.
